## 1. The Four-Tier State Taxonomy (Design Hypothesis)

To prevent the dangerous conflation of scratchpad thoughts with authoritative privileges, gibbrn decomposes all agent state into four formally separated, typed categories.

```
+-----------------------------------------------------------------------------------+
|                                 GIBBRN STATE TAXONOMY                             |
+-----------------------------------------------------------------------------------+
|  [COGNITIVE STATE]            |  [OPERATIONAL STATE]                              |
|  - Probabilistic, model-owned |  - Derived from experience, externally validated  |
|  - Ephemeral beliefs, plans   |  - Versioned skills, tool heuristics, workflows   |
|  - CANNOT grant authority     |  - Admitted via regression test suites            |
+-------------------------------+---------------------------------------------------+
|  [AUTHORITATIVE STATE]        |  [RUNTIME / SAFETY STATE]                         |
|  - Canonical, deterministic   |  - Durable, lifecycle-aware, causal               |
|  - Delegations, token scopes  |  - Prospective intentions, checkpoints, receipts  |
|  - Model CANNOT directly write|  - Cross-trajectory risk ledger, anomaly counters |
+-----------------------------------------------------------------------------------+
```

### 1.1 Category A: Cognitive State ($\mathcal{S}_{\text{cog}}$)
*   **Definition:** The internal, probabilistic representations generated by the foundation model during reasoning and inference.
*   **Constituents:** Working scratchpads, chain-of-thought tokens, semantic summaries, unverified hypotheses, episodic reflections, context embeddings.
*   **Properties:** High plasticity, non-deterministic, subject to hallucination and epistemic drift. 
*   **Authority Boundary:** $\mathcal{S}_{\text{cog}}$ is treated by the system as strictly untrusted user-space data. It can *propose* actions or request state changes, but it possesses zero inherent authority to execute mutations.

### 1.2 Category B: Operational State ($\mathcal{S}_{\text{ops}}$)
*   **Definition:** Reusable procedural knowledge, tool-invocation heuristics, API integration recipes, and environment-specific navigation routines accumulated over time.
*   **Constituents:** Verified tool sequences, repository-specific debugging playbooks, parsing schemas, recovery macros.
*   **Properties:** Version-controlled, immutable once admitted, attributed to specific provenance trajectories, revocable.
*   **Admission Standard:** Cannot be committed directly by the model. Promotion into $\mathcal{S}_{\text{ops}}$ requires passing an external deterministic or test-backed validation pipeline.

### 1.3 Category C: Authoritative State ($\mathcal{S}_{\text{auth}}$)
*   **Definition:** The canonical set of permissions, capability tokens, spending quotas, delegation chains, and policy invariants governing what the agent is legally and computationally allowed to do.
*   **Constituents:** Ephemeral cryptographic capabilities, OAuth refresh token scopes, per-run dollar budget limits, rate limits, directory read/write boundaries, human sign-off mandates.
*   **Properties:** Deterministic, externally enforced, append-only event source.
*   **Integrity Guarantee:** Foundation models may inspect $\mathcal{S}_{\text{auth}}$ to plan actions, but they are physically isolated from writing to $\mathcal{S}_{\text{auth}}$. Transitions are mediated exclusively by external human operators, parent orchestrators, or deterministic cryptographic reducers.

### 1.4 Category D: Runtime & Safety State ($\mathcal{S}_{\text{safe}}$)
*   **Definition:** The persistent, durable substrate recording the operational lifecycle, pending prospective intentions, causal execution graph, and cumulative risk profile of the agent.
*   **Constituents:** Run/step identifiers, causal DAG pointers, execution checkpoints, external effect receipts (idempotency keys), prospective intentions (commitments awaiting future trigger conditions), accumulated anomaly scores, policy violation logs.
*   **Properties:** Fully durable, replayable, monotonic, cross-trajectory (lifetime-scoped).

## 3. Formal System Invariants

We define five core invariants that gibbrn guarantees across all execution lifecycles.

### Invariant 1: Non-Laundering of Authority (Anti-Laundering Principle)
*Status: ESTABLISHED REQUIREMENT*

> **Formal Statement:** An agent's cognitive reflection or context-window assertion cannot synthesize, elevate, or modify authoritative capability state.

$$\forall \Delta \mathcal{S}_{\text{auth}}, \quad \text{Origin}(\Delta \mathcal{S}_{\text{auth}}) \in \mathcal{E}_{\text{external}} \cup \mathcal{R}_{\text{deterministic}} \quad \land \quad \text{Emitter}(\Delta \mathcal{S}_{\text{auth}}) \neq \text{LLM}_{\text{cognitive}}$$

*Where:*
- $\mathcal{E}_{\text{external}}$ represents signed events from human operators, enterprise IAM systems, or parent supervisory processes.
- $\mathcal{R}_{\text{deterministic}}$ is a mathematically provable state reducer operating over previously verified events.
- $\text{LLM}_{\text{cognitive}}$ is any model-generated token sequence.

### Invariant 2: Cryptographic Provenance Lineage
*Status: ESTABLISHED REQUIREMENT*

> **Formal Statement:** Every committed state mutation in operational or safety state must possess a verifiable, acyclic causal lineage linked to a root event.

$$\forall s_t \in \mathcal{S}_{\text{ops}} \cup \mathcal{S}_{\text{safe}}, \quad \exists \mathcal{L}(s_t) = \langle e_0, e_1, \dots, e_t \rangle \quad \text{s.t.} \quad \text{Hash}(e_i) = \mathcal{H}(e_i.\text{payload} \parallel \text{Hash}(e_{i-1}))$$

No state update can be promoted or acted upon as a dependency without an unbroken hash-chain demonstrating:
1. The exact trajectory ID where the observation occurred.
2. The specific tool invocation and raw environment receipt.
3. The identity of the foundation model and prompt template that proposed the transition.

### Invariant 3: Pre-Effect Capability and Policy Evaluation
*Status: ESTABLISHED REQUIREMENT*

> **Formal Statement:** No external environment mutation can be triggered without an atomic, pre-execution evaluation against the canonical authoritative state and risk ledger.

Let $a$ be a proposed action targeting an external system effect $\mathcal{E}_{\text{ext}}$. The execution gate function $\mathcal{G}$ must satisfy:

$$\mathcal{G}(a, \mathcal{S}_{\text{auth}}, \mathcal{S}_{\text{safe}}) = \begin{cases} 
\text{ALLOW}, & \text{if } \text{ReqCaps}(a) \subseteq \text{ActiveCaps}(\mathcal{S}_{\text{auth}}) \;\land\; \text{RiskMetric}(\mathcal{S}_{\text{safe}} \cup \{a\}) \le \theta_{\text{threshold}} \\
\text{DENY}, & \text{otherwise}
\end{cases}$$

Under no circumstances may an agent dispatch network, filesystem, or transactional API calls directly from raw model token emissions without passing through $\mathcal{G}$.

### Invariant 4: Externally Grounded Experience Admission
*Status: RESEARCH HYPOTHESIS (To be tested in RQ4)*

> **Formal Statement:** An empirical observation or candidate operational skill $\sigma_{\text{cand}}$ cannot be admitted into canonical operational state $\mathcal{S}_{\text{ops}}$ based solely on model self-evaluation.

$$\sigma_{\text{cand}} \xrightarrow{\text{Promote}} \mathcal{S}_{\text{ops}} \iff \mathcal{V}_{\text{external}}(\sigma_{\text{cand}}) = \text{PASS} \quad \land \quad \Delta \text{Performance}(\text{RegressionSuite}, \sigma_{\text{cand}}) \ge -\epsilon$$

*Where:*
- $\mathcal{V}_{\text{external}}$ is an automated validator independent of the generative model (e.g., test suite execution, static type checker, deterministic parser).
- $\text{RegressionSuite}$ is a benchmark of frozen canonical tasks preventing catastrophic forgetting or performance degradation.

### Invariant 5: Prospective Intention Lifecycle Completeness
*Status: RESEARCH HYPOTHESIS (To be tested in RQ5)*

> **Formal Statement:** Every prospective agent commitment $I$ is represented as a formal state machine with deterministic terminal conditions, independent of context window compaction.

```
       +--------------+
       |   PENDING    | <----------------------+
       +--------------+                        |
              |                                |
       (Trigger Fired)                         |
              v                                |
       +--------------+                        |
       |  ACTIVATED   |                        |
       +--------------+                        |
        /     |      \                         |
       /      |       \                        |
(Success)  (Fail)   (Timeout / Cancel)         |
     /        |         \                      |
    v         v          v                     |
+-------+ +-------+ +---------+                |
|FULFILL| |RETRY  |-+ (Backoff < MaxRetries)  |
+-------+ +-------+                            |
              | (Exhausted)                    |
              v                                |
        +-----------+                          |
        | DEADLETTER| -------------------------+ (Requires Human Review)
        +-----------+
```

An intention $I = \langle \text{ID}, \text{Condition}, \text{ActionPayload}, \text{ExpiryTime}, \text{CapabilityCap} \rangle$ persists in durable storage. If context compaction occurs, $I$ remains active in $\mathcal{S}_{\text{safe}}$ and is deterministically re-injected into working memory when $\text{Condition}$ evaluates to true.

## 4. Operational Knowledge Lifecycle & Quarantine State Machine

To prevent unvalidated or poisoned experience from silently corrupting future trajectories, candidate operational knowledge transitions through the rigorous state machine detailed in Figure 3.1.

```
Raw Execution Trajectory (Flight Recorder Log)
                   |
                   v
    [Candidate Extraction Phase]
   (Model identifies recurring pattern)
                   |
                   v
       +-----------------------+
       |  STATE: CANDIDATE     |
       +-----------------------+
                   |
       (Automated Syntax & Safety Scan)
                   |
         +---------+---------+
         | Passes            | Fails
         v                   v
+------------------+   +------------------+
| STATE: QUARANTINE|   | STATE: REJECTED  |
+------------------+   +------------------+
         |
(Regression Suite & Sandbox Execution)
         |
    +----+----+
    |         |
 (Passes)  (Regresses or Errors)
    |         |
    v         v
+----------+ +------------------+
|  ACTIVE  | | STATE: QUARANTINE| (Flagged for Developer Review)
|  SKILL   | +------------------+
+----------+
    |
(Subsequent Failure in Production)
    |
    v
+--------------------+
|  STATE: REVOKED    | (Immediate Causal Rollback)
+--------------------+
```

### Transition Semantics
1.  **Candidate $\to$ Quarantine:** When an agent successfully solves a novel task, the extracted heuristic is isolated. It is tagged with `Status: QUARANTINE` and cannot be retrieved by production agents.
2.  **Quarantine $\to$ Active:** The skill is executed against a headless test suite within a micro-sandbox. If it generates no security violations and demonstrates a statistically significant efficiency or accuracy gain, it is cryptographically signed and promoted to `Active`.
3.  **Active $\to$ Revoked:** If an active skill subsequently correlates with downstream runtime errors, an automated causal attribution routine flags the skill, transitioning it to `Revoked` and purging it from active retrieval projections.
